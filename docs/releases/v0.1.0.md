# CIProof v0.1.0

## What CIProof is

CIProof is a deterministic behavioral verifier for GitHub Actions. Instead of
matching dangerous-looking YAML patterns, it explores the modeled execution
scenarios of your workflows and, when an invariant can be violated, prints a
concrete counterexample — or reports `UNKNOWN` when it cannot decide soundly. No
workflow is executed and no secrets are required.

## Highlights

- **Invariant verification** — built-in checks plus user-declared invariants in
  `ciproof.yml` (`job-requires-job`, `job-not-reachable`, `job-only-reachable`).
- **Concrete counterexamples** — every REFUTED result carries a real, explored
  scenario and the relevant job states.
- **Semantic behavior diff** — `ciproof diff <base>...<head>` reports how modeled
  CI behavior changed between two git revisions, not a textual diff.
- **Machine-readable reporting** — stable JSON (version 1) and SARIF 2.1.0.
- **GitHub Actions integration** — emit SARIF for code scanning; the exit code is
  identical across output formats.

## Validation

Measured on a pinned corpus of **50 public repositories / 295 workflows**
(reproduce with `npm run validate:corpus`):

- 45.2% of analyzed workflows fully modeled; 54.8% partial (semantic `UNKNOWN`);
  1 workflow rejected by GitHub's own parser.
- 18/18 controlled semantic-compatibility cases matched documented GitHub
  behavior (0 false RUN/SKIP/BLOCK).
- All 10 concrete counterexamples in the corpus were manually confirmed
  (0 false positives).

These figures are specific to the pinned corpus and audited sample; they are not
claims of universal accuracy. Full methodology is in
[docs/validation-study.md](../validation-study.md).

## Supported semantics

Events `push`, `pull_request`, `pull_request_target`, `workflow_dispatch`,
`schedule`, `workflow_run`; branch/tag/path filters; `jobs.<id>.if`, `needs`,
`permissions`; boolean & choice dispatch inputs; static matrices; local reusable
workflows; informational `concurrency`. Full details:
[docs/supported-semantics.md](../supported-semantics.md).

## Important limitations

- **CIProof is bounded.** It models a subset of GitHub Actions; everything else
  is `UNKNOWN`.
- **`UNKNOWN` means CIProof cannot soundly determine the result** — it is never a
  pass.
- **`NO VIOLATION FOUND` is not universal proof** — only that no violation exists
  among the modeled scenarios.
- External reusable workflows, dynamic matrices, runtime `needs.*.outputs.*`, and
  unsupported triggers are `UNKNOWN`.
- `ciproof diff` requires `git` on `PATH`.
